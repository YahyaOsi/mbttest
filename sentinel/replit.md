# Sentinel

A private Solana trading control center with live token discovery, AI evidence assessment, paper trading, and explicitly gated mainnet execution.

## Current reliability and risk policy

This section supersedes conflicting historical strategy notes below. **Why:** the owner now prioritizes execution reliability, measurable quality and positive expectancy over raw trade volume.

Endpoint identities—not credential-bearing URLs—belong in balance audit logs.
- Optional Jito is **off by default**. Only bounded unsigned swap transactions receive an atomic tip before simulation/signing. - New holdback defaults to **0.1%**, configurable down to zero. Existing positions keep their snapshotted raw protection/legacy 1%; settings must never release an already protected reserve.
- New adaptive moon-bag defaults sell **20% original at +60%, 50% at +100%, 20% at +150%**. Remaining tradable tokens trail, tightening after large moves. Volatility stops can tighten but never widen the hard stop. Old position snapshots are immutable; do not migrate their exit plans during monitoring.
- Canonical pipeline labels are observed, awaiting-market, active-watch, eligible, rejected-permanent, order-attempted, filled. Durable registry deadlines—not stale labels—define active watches.
- The additive `sentinel_diagnostics` journal commits atomically with account snapshots and is independent of the 500-event UI list. Apply its development-to-production schema migration during publishing before enabling the new worker. Do not add production startup DDL. ## Architecture decisions

- Admit standard SPL mints and explicitly supported metadata-only Token-2022 mints. Reject transfer-altering or unknown extensions; derive ATAs using the mint's actual token program and retain instruction/simulation safeguards.
- Unknown safety/quote/AI data blocks entries. Never substitute simulated data for live observations.
- Only the explicitly configured owner can invoke mutating controls or incur AI analysis costs. Never claim the first signup as owner.
- Pending signed transactions are persisted before submission and reconciled by signature; never clear or resubmit an ambiguous order automatically.
- Keep entry scanning and exit monitoring independent. Pause blocks buys but does not abandon positions.

## Product

- Background discovery in Crazy Mode runs every two minutes while position checks, new live Pump bursts and owner-enabled tracked-wallet events use independent loops. General paid AI sweeps run every ten minutes and Watching AI every five minutes within the configured 1,440 daily-request maximum. Once exhausted, every scan makes deterministic BUY/REJECT watchlist decisions without paid calls; BUY still requires fresh safety and existing execution guards.
- New aggressive/copy positions sell 50% of original tokens at +100% net SOL gain and trail the sellable remainder by 15%, retaining 1% permanently. Full/staged/adaptive settings remain for other conservative entries. Snapshot exits per position; never infer original quantity from a partial remainder or advance tiers before finalized reconciliation. Existing exposure retains its prior policy. Stop-loss, emergency and daily-loss controls override targets.
- AI evidence scores are not calibrated probabilities or promises of profitability.
- Discovery combines verified Pump.fun launches, Jupiter lists, and DEX Screener profiles, including supported ordinary SOL/LP-protected pools. It is not a complete archive of all launches. Exact-mint analysis and a durable 15-minute watchlist exist. Owner-configured Solana wallets may be watched in any mode; X usernames need an explicitly supplied wallet, while FOMO names without one resolve only when the independent fresh public top-ten board provides a verified linked wallet. Posts/social alerts are not connected.
- Paper fills use real native SOL/token quotes, full slippage cushion, $0.03 estimated fee/fill and 0.00204 SOL entry account-rent allowance; they do not prove real fills. Finalized live SOL wallet movements include fees and account rent. USD reporting uses reference-price estimates; token profitability in SOL and USD can differ.

## Gotchas

- No high-win-rate or "works perfectly" claims. Do not enable live trading without explicit setup, spending limits and controlled execution/restart verification.
- Add provider credentials and private keys only through Secrets. Never accept key material in chat, browser forms, code, logs or memory.
- The user wants a fresh burner private key on the server, no browser-wallet connection, and native SOL→token→SOL trading. Fund only the independently verified burner address with SOL. Default protected reserve is 0.005 SOL, configurable with a 0.003 SOL minimum. USD position caps are converted using a fresh SOL/USD reference.
- Profit targets, trailing stops and trade win-rate use SOL returns; USD P&L is reported separately. SOL/USD appreciation alone must not authorize a profit exit. Very small entries are skipped if estimated fees/rent/slippage already breach their stop-loss limit.
- This app is for the creator's personal use only: one owner, one password, no public signup, no public token feed or private API access. Set SENTINEL_APP_PASSWORD (16–256 characters) securely. No email, Clerk account or owner-ID configuration is needed. A previously configured SENTINEL_OWNER_USER_ID is retained only as a legacy ledger key, not an authentication mechanism.
- Session tokens are random, stored as hashes in PostgreSQL, expire after 12 hours and are revoked on logout or password/session-secret rotation. Login attempts are durably rate-limited. HTTPS-only HTTP-only partitioned cookies support embedded preview; all writes require a matching HTTPS Origin. Locking the UI must not pause unattended trading.
- The creator may use one burner wallet or replace it. Before switching: pause, close all live positions using the old key and reconcile pending signatures, replace the private key in Secrets, restart, then independently verify the new public address in Setup. Never bind another wallet while live exposure exists. Preserve old-wallet history and do not mix its cash or P&L with a new wallet.
- Live gating additionally requires `SOLANA_RPC_URL`, `JUPITER_API_KEY`, `SOLANA_TRADING_PRIVATE_KEY`, `ENABLE_MAINNET_TRADING=true`, and an always-on deployment confirmation (`SENTINEL_ALWAYS_ON_CONFIRMED=true`).
- Use a separate low-balance wallet; unattended server-held signing can expose that entire wallet if compromised.
- Keep AI costs low for the user's small budget. gpt-5-nano uses minimal reasoning, a 1,024-token output cap and no billed automatic retries. Manual and automatic analysis share one durable interval and daily cap. Cached evidence requires fresh filters/safety and similar market facts; changed/expired evidence waits for the next paid assessment. A request cap is not a dollar cap; AI, hosting and providers are separate from trading capital.
- Use a Reserved VM deployment for the API/worker and frontend together, not a static-only deployment. Do not implement production startup DDL; the supported publish flow applies managed DB schema.
- Mainnet execution and signed-in UI require separate verification; the initial build did not submit real-money transactions.
